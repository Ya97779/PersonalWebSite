# 高志逸个人作品集多页面改造设计

## 1. 背景与目标

当前网站是一个纯静态单页作品集：所有关于、项目、经历和能力内容都集中在 `index.html`，访客需要连续向下滚动才能读取完整信息。现有内容质量和视觉基础已经足够，但信息密度高、入口不够明确，导致首页承担了“自我介绍、案例详情、简历时间线和联系方式”四种不同任务。

本次改造的目标是把网站从“长篇连续阅读”调整为“首页总览 + 专题页面按需阅读”，同时保留纯静态部署能力和现有内容资产。

成功标准：

- 首页在首屏内清晰说明个人定位，并提供专题入口，不再承载全部详细内容。
- 顶部导航顺序固定为：`首页 / 教育经历 / 项目经历 / 实习经历 / 专业能力 / 兴趣爱好`。
- 每个专题拥有独立 URL，可以直接访问、刷新、复制和分享。
- 项目和实习详情默认收起，访客主动点击后再阅读完整材料。
- 桌面端和移动端均能使用，键盘焦点和减少动画设置可用。
- 继续使用普通静态文件部署，不引入后端、数据库或必须的构建服务。

## 2. 方案选择

### 采用：静态多页网站（Multi-Page Static Site）

新增独立 HTML 页面，共用 `styles.css` 和 `script.js`。导航使用相对路径链接，避免依赖前端路由或服务器端重写。

推荐理由：

- 直接解决内容集中和长页面问题。
- 每一类内容有清晰、稳定且可分享的地址。
- 继续兼容 Nginx、GitHub Pages、Cloudflare Pages 和对象存储。
- 项目规模不需要 React、Vue 或动态后端。
- 将来若需要 CMS 或账号系统，可以在稳定的信息架构上再升级。

### 不采用的方案

- 单页 JavaScript 标签切换：文件表面上少，但所有内容仍在一个长文档里，无法解决当前维护和阅读问题。
- React/Vue 或服务器端动态渲染：会增加构建、运行和部署复杂度，当前作品集没有数据登录、后台和实时数据需求。

## 3. 页面与 URL 架构

```text
index.html          首页
education.html      教育经历
projects.html       项目经历
internship.html     实习经历
skills.html         专业能力
interests.html      兴趣爱好
styles.css          全站共享样式
script.js           全站共享交互
assets/             图片、图标和其他静态资源
```

### 3.1 全站共享壳层

每个页面保持一致的 HTML 壳层：

1. 跳过导航链接（无障碍）。
2. 固定顶部 `site-header`：品牌、主导航、联系按钮。
3. `main` 内的页面标题区和内容区。
4. 统一联系 CTA 和页脚。

品牌点击返回 `index.html`。导航链接使用完整相对路径：

```text
index.html
education.html
projects.html
internship.html
skills.html
interests.html
```

当前页面通过 `aria-current="page"` 和视觉高亮同时表达。脚本只负责根据当前路径补齐高亮、移动端菜单和内容展开，不负责页面路由。

## 4. 页面内容设计

### 4.1 首页

首页的单一任务是让访客在短时间内理解“你是谁、擅长什么、下一步看哪里”。

内容顺序：

1. Hero：`AI BUILDER`、产品思维 × 工程执行、一句精炼定位。
2. 个人简介：保留现有关于我核心文案和头像，压缩为一段摘要。
3. 核心成果：RAG +20%、AI Workflow 80%、机器人 ±3cm、交付 100%。
4. 专题入口：教育经历、项目经历、实习经历、专业能力、兴趣爱好五张入口卡片。
5. 联系 CTA：邮箱和“聊一聊”。

首页不放完整项目 bullet、完整实习细节、教育奖项列表或全部项目截图。入口卡片必须有明确的动作文案，例如“查看项目经历”。

### 4.2 教育经历页

只包含教育经历，不与实习时间线混排：

- 南开大学｜人工智能硕士｜2024.09 — 2027.06
- 武汉理工大学｜自动化本科｜2020.09 — 2024.06

使用一条垂直成长轨迹表达“自动化基础 → 人工智能 → LLM/Agent 实践”。学位、方向、奖项和竞赛作为每个条目的可展开详情。保留现有已确认的奖学金、软件著作权和竞赛信息，不新增未提供的经历。

### 4.3 项目经历页

保留现有四个项目，页面顶部先给出项目目录和成果摘要：

1. 健身助手 Agent
2. 智能穿戴健康 iOS App
3. 移动机器人底盘
4. LLM-Wiki 团队知识服务

每张项目卡默认显示：项目分类、名称、一句话价值、成果数字、技术标签和一张代表图。完整背景、个人职责、技术方案、项目要点和剩余图片放入原生 `<details>` 展开区，使用明确的“查看完整案例 / 收起案例”状态。

项目视觉示意图和现有 `assets/projects` 图片继续复用，图片设置 `loading="lazy"` 和有意义的中文 `alt` 文本。

### 4.4 实习经历页

只包含两段实习：

- 网联清算有限公司｜AI 应用开发实习生｜2026.07 — 2026.08
- 璐珩智能科技有限公司｜机器人软件实习生｜2025.05 — 2026.03

每段经历以时间、职位、组织和一句结果摘要开场，原有知识服务、Agent、需求拆解、导航、业务闭环和工具交付内容放入可展开详情。时间顺序按最新在前，页面不再包含教育条目。

### 4.5 专业能力页

保留现有三层能力叙事：

1. 理解问题
2. 设计智能
3. 完成交付

三张主卡后增加按领域分组的能力矩阵：AI 应用、后端工程、智能硬件、产品实践。矩阵只使用现有内容中已经出现的技术和能力词，避免制作与履历不一致的“技能清单”。

### 4.6 兴趣爱好页

先使用可替换草稿，明确这是从现有项目和描述提炼出的兴趣方向，不将推测写成正式经历：

- 健身与训练：关注长期计划、数据反馈和习惯养成。
- 机器人与智能硬件：喜欢观察软件如何进入真实世界。
- AI 工具与产品：持续研究 Agent、知识库和自动化工作流。
- 知识整理：喜欢把复杂信息整理成清晰、可复用的结构。

每个兴趣以短文、关键词和一件相关项目/实践作为内容锚点。页面留出后续替换成个人真实故事、照片或链接的空间。

## 5. 视觉系统

### 5.1 设计方向

采用“精炼的工程编辑感”：保留当前深色、暖白、橙红信号色的辨识度，减少重复大标题、过多装饰和长段落堆叠。导航和页面编号成为主要秩序工具。

### 5.2 颜色令牌

```css
--ink: #0b0d0f;          /* 主深色背景 */
--ink-soft: #15191c;     /* 卡片和层级背景 */
--paper: #f1eee6;        /* 主内容背景 */
--paper-deep: #dedad0;   /* 次级内容背景 */
--white: #fbfaf6;        /* 深色区域文字 */
--muted: #858b8f;        /* 辅助文字 */
--accent: #ff5a36;       /* 当前导航、重点和 CTA */
--signal: #bdeec7;       /* 可用、交付、状态标签 */
--line-dark: rgba(255,255,255,.16);
--line-light: rgba(11,13,15,.16);
```

保留现有圆角和细线语言，但降低大面积橙色使用频率。橙色只承担“这里重要 / 点击这里 / 这是当前页面”的语义。

### 5.3 字体与排版

- 英文展示：使用系统可用的几何无衬线字体栈，粗体大写仅用于页面标识和短标题。
- 中文正文：使用 `PingFang SC`、`Microsoft YaHei` 等系统字体，控制行长和行高以提升阅读舒适度。
- 页面标题使用“英文页面编号 + 中文标题 + 一句总结”的组合，不用重复的 01/02/03 装饰。
- 正文宽度限制在易读范围；长段落拆成摘要、列表和展开详情。

### 5.4 记忆点

全站采用固定的“页面控制栏”：顶部导航显示当前栏目，页面标题区显示 `PAGE / 01` 等标识，橙色只沿着当前页和可行动作出现。访客可以在任何页面快速知道自己在哪里、还能去哪里。

## 6. 交互与响应式

- 桌面端顶部导航横向排列；屏幕较窄时切换为菜单按钮。
- 菜单按钮有可读的 `aria-expanded` 和 `aria-controls`，打开后可通过按钮关闭。
- 页面首次进入时不自动滚动到隐藏锚点，避免多页导航造成位置错乱。
- `<details>` 负责项目和实习详情展开，保持原生键盘、读屏和无脚本可用性；脚本只增强标签文案和动画。
- `IntersectionObserver` 继续用于轻量内容显现，但在 `prefers-reduced-motion: reduce` 时直接显示。
- 保留 Hero 的鼠标光效，但限制在支持精细指针的设备，并尊重减少动画设置。
- 所有链接、按钮和菜单项保持明显的 `:focus-visible` 样式。
- 断点重点覆盖 1080px、820px、620px 三档，保证导航、卡片、时间线和图片在手机上不横向溢出。

## 7. 内容迁移规则

1. 从现有 `index.html` 迁移内容，不改动已确认的事实、日期、公司、学校、技术栈和成果数字。
2. 现有首页关于我内容保留摘要版；完整素材只出现在对应专题页。
3. 项目图片路径统一使用 `assets/projects/...`，不复制图片文件。
4. 所有页面共享同一份 `styles.css` 与 `script.js`，避免每页出现不同的导航样式。
5. 删除旧的区块内锚点导航，改为页面路径导航；保留页面内部必要的目录锚点时使用短、稳定的 id。
6. 兴趣页文案标记为草稿性质，后续可直接替换，不影响其他页面结构。

## 8. 部署与兼容性

改造后仍是可直接托管的静态目录。部署步骤不变：上传整个项目，确保站点根目录的默认文档为 `index.html`，配置域名和 HTTPS 即可。

由于使用真实 `.html` 文件而不是客户端路由，GitHub Pages、Nginx、Cloudflare Pages 和对象存储无需额外的 SPA fallback 配置。所有页面使用相对链接，因此部署到子路径也能正常工作。

## 9. 验收与验证

### 静态检查

- 确认六个 HTML 页面存在，并且都能引用 `styles.css`、`script.js`。
- 检查导航顺序、链接路径和 `aria-current`。
- 检查所有图片路径存在，图片 `alt` 不为空。
- 检查旧的 `#profile`、`#journey` 等单页导航不会残留在主导航中。

### 本地运行检查

使用 README 中的命令：

```bash
python -m http.server 4173
```

逐页访问首页、教育、项目、实习、能力和兴趣页面，验证导航、移动菜单、详情展开、邮箱链接和返回首页。

### 响应式与可访问性检查

- 桌面宽度：导航不换行溢出，内容最大宽度稳定。
- 手机宽度：菜单可打开和关闭，卡片变为单列，图片不超出视口。
- 键盘：可通过 Tab 访问导航、菜单、详情和 CTA，焦点可见。
- 减少动画：页面内容直接可见，不依赖动画触发阅读。

## 10. 范围外

- 不引入登录、评论、后台编辑、数据库或动态 API。
- 不重写为 React/Vue/Next 等框架。
- 不新增未经用户确认的履历、联系方式或项目数据。
- 不删除现有图片资产和优化脚本。
